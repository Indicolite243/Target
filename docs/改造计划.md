# Target 后续改造计划

## 待规划：新用户绑定 QMT 账户引导

### 目标

- 新用户注册后默认进入独立的 `SIM-*` 本地模拟账户。
- 在账户页面增加“绑定 QMT 账户”引导，帮助用户区分模拟账户与 QMT 账户。
- 绑定成功后明确展示 QMT 账户的脱敏账号、连接状态、数据来源和最近同步时间。
- 未绑定、QMT 未登录、账户不可用和绑定失败等状态提供明确提示。

### 当前限制

- 当前 QMT 连接由部署级配置 `QUANT_QMT_PATH`、`QUANT_QMT_ACCOUNT_ID` 和单个 MiniQMT 会话决定，并非每个系统用户独立配置。
- 现有系统应继续保证新用户只能读取自己的 `SIM-*` 模拟账户，不能因引导功能读取其他用户的 QMT 账户。
- 开放自助绑定前，需要先完成 QMT 外部账户与系统用户的归属校验，防止多个用户绑定或读取同一资金账户。
- 若未来支持多用户/多 QMT 账户，还需要让 FastAPI/QMT 适配层按绑定关系读取账户，不能只返回全局 `.env` 配置的账户数据。
- 绑定流程默认只允许只读同步；真实交易开关必须保持关闭，除非用户明确开启并完成额外安全确认。

### 预期改造范围

- 前端：账户页增加绑定入口、状态引导、失败原因和解绑/重新绑定入口。
- Spring Boot：增加 QMT 账户探测、绑定、归属校验和绑定状态接口。
- 数据库：补充外部 QMT 账户映射及唯一约束，保留当前 `SIM-*` 模拟账户。
- FastAPI/QMT：支持按绑定账户读取并返回账户资产、持仓和连接状态。
- 安全与一致性：增加绑定审计、账户隔离、重复绑定防护和只读模式提示。
