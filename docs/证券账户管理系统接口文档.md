## 1. 接口公共规范

### 1.1 服务地址

| 环境 | Vue 调用 Spring Boot | Spring Boot 调用 Python | 说明 |
| --- | --- | --- | --- |
| 本地开发 | `http://localhost:8080/api/v1` | `http://localhost:8000/internal/v1` | Vue 推荐使用 Vite Proxy 调用 `/api/v1` |
| Docker 开发 | `http://localhost/api/v1` | `http://python-quant-service:8000/internal/v1` | 服务间通过 Docker 网络访问 |
| 生产 | `https://<业务域名>/api/v1` | 内网地址，不公开 | 全部外部请求使用 HTTPS |

### 1.2 数据格式

- 请求和响应默认使用 `application/json; charset=UTF-8`。
- 文件内容不经过普通 JSON 接口传输，使用 OSS 直传或临时下载地址。
- JSON 字段统一使用 `camelCase`。
- 数据库字段可使用 `snake_case`，由后端 DTO 映射，禁止直接把数据库对象暴露给前端。
- 金额、价格和比例在 JSON 中推荐使用字符串，避免 JavaScript 浮点误差。
- 时间使用 ISO 8601，包含时区，例如 `2026-08-05T10:30:00+08:00`。
- 交易日期使用 `yyyy-MM-dd`，例如 `2026-08-05`。
- 空值使用 `null`，不要使用 `0` 或空字符串代替“未知”。

### 1.3 公共请求头

| 请求头 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `Authorization` | string | 登录接口除外 | `Bearer <accessToken>` |
| `Content-Type` | string | 有请求体时 | 通常为 `application/json` |
| `X-Request-Id` | string | 建议 | 前端生成 UUID；用于全链路追踪和部分幂等判断 |
| `X-Idempotency-Key` | string | 下单等写接口必须 | 同一业务动作的唯一键，建议 UUID |
| `X-Client-Version` | string | 建议 | Vue 应用版本，例如 `web-1.0.0` |
| `Accept-Language` | string | 否 | 默认 `zh-CN` |

### 1.4 统一成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "7f1564d6e68a4b76b516edb64d0e9f42",
  "timestamp": "2026-08-05T10:30:00+08:00"
}
```

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `code` | integer | 是 | `0` 表示业务成功，非 0 表示业务失败 |
| `message` | string | 是 | 面向调用方的简要信息 |
| `data` | object/array/null | 是 | 业务数据，无数据时为 `null` |
| `traceId` | string | 是 | 后端链路追踪 ID，可用于日志排查 |
| `timestamp` | string | 是 | Spring Boot 响应生成时间 |

### 1.5 统一失败响应

```json
  "code": 400100,
  "message": "请求参数校验失败",
  "data": {
    "fieldErrors": [
```

### 1.7 HTTP 状态码

| HTTP 状态 | 使用场景 |
| --- | --- |
| `200 OK` | 查询成功、同步写操作完成 |
| `201 Created` | 用户、订单、规则等资源创建成功 |
| `202 Accepted` | 账户同步、风险重算、文件导入等异步任务已受理 |
| `204 No Content` | 删除成功且不需要响应体；本项目也可统一返回 200 |
| `400 Bad Request` | 参数格式错误、业务参数不合法 |
| `401 Unauthorized` | 未登录、Access Token 无效或过期 |
| `403 Forbidden` | 已登录但无资源权限 |
| `404 Not Found` | 资源不存在或对当前用户不可见 |
| `409 Conflict` | 重复资源、状态冲突、重复提交 |
| `422 Unprocessable Entity` | 文件内容或复杂业务校验失败 |
| `429 Too Many Requests` | 行情查询、登录等接口触发限流 |
| `500 Internal Server Error` | 未处理的服务器异常 |
| `502 Bad Gateway` | Python 或外部数据源返回无效结果 |
| `503 Service Unavailable` | Python/QMT/行情源暂时不可用 |
| `504 Gateway Timeout` | 调用 Python 或外部数据源超时 |

| 错误码 | HTTP 状态 | 说明 |
| --- | --- | --- |

| `409302` | 409 | 当前订单状态不允许该操作 |

| `503301` | 503 | 交易服务暂时不可用 |
| `504601` | 504 | Python 服务调用超时 |

### 1.9 数据新鲜度元信息

行情、账户、风险和分析接口应根据需要返回以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dataTime` | string | 业务数据实际对应的时间，不是 HTTP 响应时间 |
| `source` | string | `redis`、`mysql`、`mongodb`、`qmt`、`baostock`、`mock` 等 |
| `stale` | boolean | 是否为过期数据或降级缓存 |
| `dataVersion` | string | 数据快照版本或最后同步版本 |
| `algorithmVersion` | string | 风险或策略算法版本 |
| `environment` | string | `SIMULATION` 或 `REAL` |

### 1.10 幂等规范

- 下单、撤单、文件完成确认等可能重复提交的接口使用 `X-Idempotency-Key`。
- 同一个用户、同一个接口、同一个幂等键必须返回首次处理结果。
- 同一个幂等键对应不同请求体时返回 `409301`。
- 前端超时后不得生成新幂等键直接重复下单，应先查询原订单状态。

## 2. 认证与用户接口

### 2.1 用户注册

#### 2.1.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 请求路径 | `/api/v1/auth/register` |
| 请求方式 | `POST` |
| 登录要求 | 否 |
| 接口状态 | 设计中 |
| 接口描述 | 创建本地用户账号，默认赋予普通用户角色 |
| 主要数据源 | MySQL `sys_user`、`sys_user_role` |

#### 2.1.2 请求参数

请求体格式：`application/json`

| 参数名 | 类型 | 必须 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| `username` | string | 是 | 4 至 32 位，字母/数字/下划线 | 登录用户名 |
| `password` | string | 是 | 8 至 64 位，至少包含两类字符 | 原始密码只用于本次传输 |
| `confirmPassword` | string | 是 | 必须等于 `password` | 确认密码 |
| `displayName` | string | 否 | 最长 50 位 | 显示名称 |

请求示例：

```json
{
  "username": "investor01",
  "password": "Example@123",
  "confirmPassword": "Example@123",
  "displayName": "投资者一号"
}
```

#### 2.1.3 响应数据

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.userId` | string | 用户 ID，推荐雪花 ID 字符串 |
| `data.username` | string | 用户名 |
| `data.displayName` | string | 显示名称 |
| `data.roles` | string[] | 默认包含 `USER` |
| `data.createdAt` | string | 创建时间 |

成功示例：

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "userId": "10001",
    "username": "investor01",
    "displayName": "投资者一号",
    "roles": ["USER"],
    "createdAt": "2026-08-05T10:30:00+08:00"
  },
  "traceId": "...",
  "timestamp": "2026-08-05T10:30:00+08:00"
}
```

#### 2.1.4 业务与性能说明

- 密码使用 BCrypt 哈希后写入 MySQL，禁止保存原始密码。
- `username` 依靠 MySQL 唯一索引防止并发重复注册。
- 可按 IP 和设备做低频限流，例如每分钟不超过 5 次。

### 2.2 用户登录

#### 2.2.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 请求路径 | `/api/v1/auth/login` |
| 请求方式 | `POST` |
| 登录要求 | 否 |
| 接口描述 | 校验用户名密码，签发 Access Token 和刷新会话 |
| 主要数据源 | MySQL 用户/角色；Redis 刷新会话与登录限流 |

#### 2.2.2 请求参数

| 参数名 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |
| `rememberMe` | boolean | 否 | 是否延长刷新会话；默认 `false` |

```json
{
  "username": "investor01",
  "password": "Example@123",
  "rememberMe": true
}
```

#### 2.2.3 响应数据

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.accessToken` | string | JWT Access Token |
| `data.tokenType` | string | 固定为 `Bearer` |
| `data.expiresIn` | integer | Access Token 剩余秒数 |
| `data.user` | object | 当前用户摘要 |
| `data.user.userId` | string | 用户 ID |
| `data.user.username` | string | 用户名 |
| `data.user.displayName` | string | 显示名称 |
| `data.user.roles` | string[] | 角色列表 |
| `data.user.permissions` | string[] | 前端所需权限码 |

成功响应同时通过安全 Cookie 保存 Refresh Token：`HttpOnly; Secure; SameSite=Lax`。

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 1800,
    "user": {
      "userId": "10001",
      "username": "investor01",
      "displayName": "投资者一号",
      "roles": ["USER"],
      "permissions": ["account:read", "order:create", "risk:read"]
    }
  },
  "traceId": "...",
  "timestamp": "2026-08-05T10:30:00+08:00"
}
```

#### 2.2.4 业务与性能说明

- 前端不得把密码写入 LocalStorage。
- 连续失败应增加 Redis 计数和短期锁定，避免暴力破解。
- 登录成功后清空失败计数，记录登录审计日志，但日志不得包含密码和完整 Token。

### 2.3 刷新 Access Token

#### 2.3.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 请求路径 | `/api/v1/auth/refresh` |
| 请求方式 | `POST` |
| 登录要求 | 不要求有效 Access Token，但要求有效 Refresh Cookie |
| 主要数据源 | Redis 刷新会话 |

#### 2.3.2 请求参数

无 JSON 请求体。浏览器自动携带 HttpOnly Refresh Token Cookie。

#### 2.3.3 响应数据

```json
{
  "code": 0,
  "message": "Token 刷新成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 1800
  },
  "traceId": "...",
  "timestamp": "2026-08-05T10:40:00+08:00"
}
```

#### 2.3.4 注意事项

- 前端同一时刻最多发起一个刷新请求，其他 401 请求等待刷新结果。
- Refresh Token 过期返回 `401003`，前端清空状态并跳转登录页。

## 3. 账户管理接口

### 3.1 查询账户列表

#### 3.1.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 请求路径 | `/api/v1/accounts` |
| 请求方式 | `GET` |
| 权限 | `account:read` |
| 接口描述 | 查询当前用户有权访问的证券账户 |
| 主要数据源 | MySQL；账户概览可短期缓存 Redis |

| 参数名 | 类型 | 必须 | 默认值 | 说明 |

### 3.3 发起账户同步

#### 3.3.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 请求路径 | `/api/v1/accounts/{accountId}/sync` |
| 请求方式 | `POST` |
| 权限 | `account:sync` 且账户属于当前用户 |
| 响应状态 | `202 Accepted` |
| 主要数据源 | Redis 分布式锁；MySQL 任务表；随后调用 Python |

#### 3.3.2 请求参数

| 参数名 | 位置 | 类型 | 必须 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `accountId` | path | string | 是 | - | 账户 ID |
| `force` | body | boolean | 否 | `false` | 是否忽略普通缓存；不能绕过并发锁 |
| `includeOrders` | body | boolean | 否 | `true` | 是否同步订单和成交 |

```json
{
  "force": false,
  "includeOrders": true
}
```

#### 3.3.3 响应数据


## 12. Spring Boot 调用 Python 的内部接口

### 12.1 内部接口公共规范

Python Quant Service 不直接暴露给 Vue，也不应公开到互联网。推荐仅允许 Docker 内网、云服务器私网或安全组内的 Spring Boot 访问。

内部基础路径：`/internal/v1`

公共请求头：

| 请求头 | 必须 | 说明 |
| --- | --- | --- |
| `X-Internal-Token` | 是 | Java 与 Python 之间的服务凭证；生产环境建议升级为 mTLS/RAM 角色等 |
| `X-Trace-Id` | 是 | 沿用 Spring Boot `traceId` |
| `X-Request-Id` | 是 | 本次内部调用 ID；交易接口同时用于幂等 |
| `X-Schema-Version` | 是 | 当前为 `1` |
| `Content-Type` | 是 | `application/json` |

内部统一响应：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {},
  "traceId": "...",
  "processedAt": "2026-08-05T11:30:00+08:00",
  "durationMs": 85
}
```

内部错误示例：

```json
{
  "success": false,
  "code": "QMT_DISCONNECTED",
  "message": "QMT 交易终端未连接",
  "data": {
    "retryable": true
  },
  "traceId": "...",
  "processedAt": "2026-08-05T11:30:00+08:00",
  "durationMs": 1002
}
```

常见内部错误码：

| 错误码 | 可否重试 | 说明 |
| --- | --- | --- |
| `INVALID_REQUEST` | 否 | 参数或 Schema 不合法 |
| `ACCOUNT_NOT_CONFIGURED` | 否 | Python 端不存在账户适配配置 |
| `QMT_DISCONNECTED` | 是 | QMT 未连接或会话失效 |
| `QUOTE_SOURCE_UNAVAILABLE` | 是 | 行情源不可用 |
| `QUOTE_NOT_FOUND` | 否/视情况 | 指定证券无行情 |
| `INSUFFICIENT_SAMPLES` | 否 | 风险计算样本不足 |
| `ORDER_REJECTED` | 否 | 交易系统明确拒绝 |
| `ORDER_STATUS_UNKNOWN` | 需要查询 | 发单结果未知，不能盲目重试 |
| `CALCULATION_ERROR` | 视情况 | 数值计算异常 |
| `INTERNAL_ERROR` | 视情况 | Python 未处理异常 |

## 14. 数据库、缓存和性能对照

### 14.1 按接口选择数据源

| 接口类别 | 首选读取 | 未命中/辅助读取 | 写入 | 一致性 |
| --- | --- | --- | --- | --- |
| 登录、用户、权限 | MySQL | Redis 会话/限流 | MySQL + Redis | 强一致 |
| 账户列表/详情 | Redis 短缓存或 MySQL | 不实时调用 Python | MySQL；同步后刷新缓存 | 高一致，显示数据时间 |
| 当前持仓 | MySQL | Redis 合并最新行情 | 同步时批量写 MySQL | 高一致 |
| 最新行情 | Redis | Python/QMT/行情源 | Redis 短 TTL | 最终一致、秒级时效 |
| 历史行情 | MongoDB | Python/OSS 归档 | MongoDB 摘要或 OSS 文件 | 最终一致 |
| 订单/成交 | MySQL | Python/QMT 查询外部状态 | MySQL 状态机 | 强一致、可对账 |
| 账户历史曲线 | MongoDB | OSS 冷数据（后续） | 同步完成后追加 MongoDB | 最终一致、可补偿 |
| 风险规则 | MySQL | Redis 可短缓存 | MySQL，清理结果缓存 | 强一致 |
| 最近风险结果 | Redis | MongoDB | MongoDB + Redis | 数据/规则/算法版本一致 |
| 风险历史 | MongoDB | - | 追加 MongoDB | 不可变历史 |
| 文件列表 | MySQL | - | MySQL 元数据 | 高一致 |
| 文件内容 | OSS | - | OSS | 最终一致、补偿 |
| 异步任务 | MySQL | Redis 临时进度 | MySQL + Redis | MySQL 为最终状态 |

### 14.2 关键接口性能预算

| 接口 | P95 目标 | 超时建议 | 缓存/优化 |
| --- | --- | --- | --- |
| `POST /auth/login` | 300ms 内 | 2s | Redis 登录限流；BCrypt 成本需压测 |
| `GET /accounts` | 200ms 内 | 2s | MySQL 索引；短缓存可选 |
| `GET /accounts/{id}/positions` | 300ms 内 | 2s | MySQL 分页 + Redis MGET |
| `GET /market/quotes` 缓存命中 | 100ms 内 | 1s | Redis pipeline/MGET |
| `GET /market/quotes` 回源 | 1s 内 | 1 至 2s | Python 批量接口；最近缓存降级 |
| `POST /orders` | 尽量 2s 内 | 外部调用约 1 至 2s | 短事务、幂等；超时转 UNKNOWN |
| `GET /snapshots` | 500ms 内 | 3s | MongoDB 联合索引、降采样、点数上限 |
| 风险任务创建 | 200ms 内 | 2s | 只创建任务，不同步计算 |
| 风险实际计算 | 5 至 30s | 异步 | 版本缓存、Python 进程池/任务队列 |
| 上传策略 | 300ms 内 | 2s | STS/签名缓存；不传文件体 |
| 文件上传 | 取决于网络 | OSS 控制 | 浏览器直传、分片/断点续传 |

### 14.3 数据库索引最低要求

MySQL：

```text
sys_user(username) UNIQUE
account(user_id, account_no) UNIQUE
position(account_id, security_code) UNIQUE
trade_order(client_order_no) UNIQUE
trade_order(account_id, created_at DESC)
trade_order(account_id, status, created_at DESC)
trade_execution(order_id, execution_no) UNIQUE
risk_rule(account_id) INDEX/UNIQUE（按业务决定）
sys_file(object_key) UNIQUE
sys_file(user_id, business_type, created_at DESC)
sync_task(user_id, task_type, created_at DESC)
```

MongoDB：

```text
account_snapshots: {accountId: 1, snapshotTime: -1}
risk_assessments:  {accountId: 1, calculatedAt: -1}
portfolio_analyses:{accountId: 1, createdAt: -1}
market_daily_summary: {symbol: 1, tradeDate: -1}
```

### 14.4 Redis TTL 与失效事件

| Key | 建议 TTL | 主动失效时机 |
| --- | --- | --- |
| `quote:{market}:{symbol}` | 交易时段 1 至 5 秒；非交易 30 至 60 秒 | 新行情覆盖；市场状态变化时调整策略 |
| `account:summary:{accountId}` | 10 至 60 秒 | 账户同步成功、订单/成交引起资产更新 |
| `risk:latest:{accountId}:...` | 5 至 30 分钟 | 持仓变化、规则变化、算法升级 |
| `auth:token:blacklist:{jti}` | Access Token 剩余时间 | 自动过期 |
| `auth:refresh:{userId}:{deviceId}` | 会话有效期 | 退出、禁用用户、密码重置 |
| `lock:account-sync:{accountId}` | 大于正常同步时间，支持续期 | 任务结束可靠释放 |
| `idem:order:{userId}:{key}` | 至少覆盖交易确认周期 | 不主动提前删除 |

### 14.5 投资数据的特殊约束

- 所有价格必须包含行情时间，所有账户值必须包含最后同步时间。
- 前端显示过期数据时必须有视觉提示，不能只在调试字段里保存 `stale`。
- 订单和成交使用 `BigDecimal`/十进制字符串，禁止 `double` 参与资金运算。
- 服务端统一证券代码格式并保存市场，例如 `600000.SH`，避免同代码跨市场混淆。
- 交易日历不能简单用工作日代替；节假日和临时休市需要可靠来源。
- 查询接口可返回旧缓存，交易前校验必须使用符合交易要求的新鲜数据或由交易端最终校验。
- 风险结果必须关联输入数据版本、规则版本、算法版本和样本范围。

## 15. 联调与文档维护规则

### 15.1 单接口完成标准

每个接口开发完成必须同时满足：

1. 本文中的路径、方法、字段、错误码和实现一致。
2. Spring Boot OpenAPI/Knife4j 能显示接口和 DTO。
3. 至少有一个成功用例和一个关键失败用例测试。
4. Vue 只通过统一 `httpClient` 调用，不出现新的硬编码服务地址。
5. 涉及 Python 时，Java DTO 与 Pydantic Schema 有相同 `schemaVersion`。
6. 日志可通过 `traceId` 关联 Vue、Spring Boot、Python 和外部数据源。
7. 已明确读取哪个数据库、写入哪个数据库、是否使用缓存、缓存何时失效。
8. 已明确超时、重试、幂等和降级策略。

### 15.2 接口变更流程

- 先修改本文档，再修改实现和前端调用。
- 兼容性增加字段可在同一 API 版本进行，但前端不能依赖未文档化字段。
- 删除字段、改变字段语义或改变路径时升级 API 版本，或设置明确过渡期。
- 金额、比例、时间、订单状态等字段语义发生变化时必须记录变更日志。
- 接口文档是设计契约，OpenAPI 是实现结果，两者在每个里程碑结束时进行比对。

### 15.3 联调建议顺序

1. 健康检查和统一响应。
2. 注册、登录、刷新 Token、退出和路由守卫。
3. 账户列表、详情、持仓与模拟同步任务。
4. 历史快照、资产曲线和配置分析。
5. 批量行情、缓存过期和外部源降级。
6. 模拟下单、幂等、订单状态和撤单。
7. 风险规则、风险异步计算和历史结果。
8. 策略分析、OSS 上传、导入和报告下载。
9. 管理端、性能压测、异常演练和完整 E2E。
